## 问题1: 墙体高度不符合、过矮

### 根因分析

| 项目 | 参考数据 (HammerData) | 当前代码 (Dust2Layout) | CS:GO 实际 |
|------|----------------------|----------------------|-----------|
| 室内墙高 | 128 HU | **256 HU** | 128-192 HU |
| 边界墙高 | — | 576 HU | 512-576 HU |
| 天花板高度 | — | 288 HU (墙256 + 间隙32) | ∼192-256 HU |
| 玩家站立高度 | 72 HU | 72 HU | 72 HU |

**矛盾点**: 当前代码墙高(256)已经比参考数据(128)高出**一倍**，但用户仍感觉"过矮"。根因是：

1. **天花板 gap 太大**：墙壁 top 在 2.56，天花板在 2.88 (yOff=256)，中间 0.32 的空隙让墙壁在视觉上像是"未封顶"
2. **墙体本身视觉比例问题**：玩家 eye height 0.64，墙高 2.56 = 4x，但开阔区域的墙壁缺少高度层次感
3. **部分关键墙体偏矮**：T Spawn 周边、B Tunnels 入口、Mid 两侧建筑 — 这些区域应该用更高的建筑体量

### 修复方案

**方案 A — 调整天花板衔接 + 区域差异化墙高 (推荐)**

```typescript
// 关键改动: 天花板直接座落在墙顶，消除gap
// B Tunnels 天花板: yOff 从 256→208 (使天花板坐在墙顶)
b( 3264,  3072,  576, 6144,  32, 224, 'b-tunnels-ceiling'),

// 特定区域加高墙体:
// - T Spawn 外墙: 128→256 (视觉体量)
// - Mid 两侧建筑: 256→320 (增强中路压迫感)
// - B Outside: 128→256 (封闭感)
// - CT Spawn: 保持256 (封闭房间已够)
```

**方案 B — 统一提高所有内墙到 320 HU**

所有 `h: 256` → `h: 320`，配合天花板升至 352。效果：墙体在视觉上更加高大。

**选择: 方案 A** — 针对性修复，避免整体比例失衡。

### 具体改动清单

| # | 区域 | 改动 | 说明 |
|---|------|------|------|
| 1.1 | T Spawn 外墙 | `h: 128→256` | 后方墙体提升压迫感 |
| 1.2 | A Long 走廊天花板 | `yOff: 256→224` | 消除墙顶空隙 |
| 1.3 | Mid 两侧 mass 体量 | `h: 256→320` | 增强中路建筑压迫感 |
| 1.4 | B Tunnels 天花板 | `yOff: 256→224` | 消除b洞顶部空隙 |
| 1.5 | B Site 墙壁 | `h: 320→352` (保持一致) | B区提升空间高度 |
| 1.6 | A Site 墙壁 | `h: 320→352` | A区统一提升 |
| 1.7 | Palace 柱子 | `h: 320→384` | 宫殿柱子更显高大 |
| 1.8 | 天花板与墙高一致 | 天花板 yOff = 墙高 | 消除所有gaps |

## 问题2: B洞上下两层、旋转楼梯、拐角掩体、箱子缺失

### 现状分析

**当前已有元素**:
- ✅ 下层走廊 (4段: entrance/mid/narrow/exit)
- ✅ 上层平台 (upper-tunnels-platform)
- ✅ 上层暗区 (upper-dark)
- ✅ 直行楼梯 (b-tunnel-stairs, 16级)
- ✅ 下层掩体箱 (5个)
- ⚠️ 楼梯侧墙 (只有两侧边框)

**缺失元素**:
- ❌ **旋转楼梯**: 当前是直行楼梯，CS:GO DUST2 B洞是带拐角的楼梯
- ❌ **拐角掩体**: B洞转弯处缺少战术掩体
- ❌ **上下层视觉分隔**: 上下层之间缺少明显的平台/护栏分隔
- ❌ **B洞出口框景**: 从B洞看向B区的视觉引导
- ❌ **中间平台层**: 旋转楼梯中途的休息平台

### 修复方案

将当前直行楼梯改为 **三段式旋转楼梯**:

```
真实 DUST2 B洞楼梯结构:
  B下层 → 第一段直行 → 90°左转 → 第二段直行 → 90°左转 → 第三段直行 → B上层

当前代码:
  B下层 → 16级直行 → B上层 (无转角)
```

**具体改动清单**:

| # | 元素 | 改动内容 |
|---|------|---------|
| 2.1 | 第一段楼梯 | 从下层(z=1280)直行到中间平台(z=896), 8级 |
| 2.2 | 中间平台 | 在 z≈896 处添加 2×2 的旋转平台 |
| 2.3 | 第二段楼梯 | 从中间平台左转90°，沿X轴上升至上层(z=-256), 8级 |
| 2.4 | 拐角墙壁 | 旋转楼梯转角处添加短墙遮挡视线 |
| 2.5 | 拐角掩体箱 | 转角各平台放置小型掩体箱 |
| 2.6 | 上层护栏 | 上层平台边缘添加矮墙/栏杆 |
| 2.7 | 下层箱子补充 | 在楼梯底部和拐角各添加2个箱子 |
| 2.8 | 视觉分隔 | 上下层之间添加横梁/装饰柱 |

**新楼梯数据** (替代现有的 `...stairsX(2880, 1280, 384, 256, 0, 128, 16, 'b-tunnel-stairs')`):

```
阶段1: 直行段 (z: 1280 → 896, h: 0 → 64, 8级)
阶段2: 旋转平台 (z=896, x从2880转到3200, h=64)
阶段3: 转向段 (x: 2880 → 3200, z: 896 → 704, h: 64 → 128, 8级)  
```

## 问题3: 中门和斜坡缺失 (T家无法通过中门对狙CT家)

### 现状分析

**数据文件 (Dust2HammerData) 中 Mid 定义**:
```typescript
MID = {
  doors: { x: 0, z: 2048, width: 192, frameHeight: 64 },
  xbox: { x: 0, z: 1024, width: 96, depth: 64, height: 48 },
  ctWindow: { x: 0, z: -1280, platformHeight: 128, platformWidth: 128 },
  suicide: { x: 512, z: 3072, width: 256, depth: 256 }
}
```

**当前代码已有**:
- ✅ Mid Doors 门框 (`mid-doors-left-frame/right-frame`, 在 z=2048)
- ✅ Xbox 低箱 (`xbox`, 在 z=1024)
- ✅ CT Window 平台 (`ct-window-platform-w/e`, 在 z=-1280)
- ✅ Suicide 平台 (`suicide-ledge`, 在 z=3072)
- ⚠️ Mid Doors 木门视觉 (`dust2-mid-doors-left/right`, Props 层)

**缺失元素**:
- ❌ **Mid 斜坡**: T Spawn 到 Mid Doors 之间应该是逐渐升高的斜坡
- ❌ **T Spawn 到 Mid 的通路**: 当前代码的 T Spawn 在 z=6656, Mid Doors 在 z=2048，距离 46.08 单位，但中间走道没有坡度
- ❌ **中门对狙视线**: 虽然有 Mid Doors，但 T Spawn (z=6656) → Mid Doors (z=2048) → CT Spawn (z=-3328) 的视线可能被中间建筑遮挡

### 根因

1. **斜坡缺失**: `b( -128, 1024, 128, 4096, 256, 0, 'mid-wall-west')` 建的中路两侧墙是平直的，但实际 DUST2 中 T 出生到 Mid Doors 需要从高到低的坡度
2. **地形平坦**: 整个地图缺乏 Z 轴高度变化，导致中门对狙失去"高低差"的战术要素
3. **视野遮挡**: Top Mid 的 mass 块过于靠近中路，遮挡了 T→Mid Doors 的视线

### 修复方案

| # | 元素 | 改动内容 |
|---|------|---------|
| 3.1 | **Mid 斜坡** | 在 T Spawn(z=6656) 到 Mid Doors(z=2048) 之间添加阶梯式下降 |
| 3.2 | **斜坡段1** | z=6144→5632, 高度 0→-32, 4级阶梯 |
| 3.3 | **斜坡段2** | z=5632→5120, 高度 -32→-64, 4级阶梯 |
| 3.4 | **斜坡段3** | z=5120→4608, 高度 -64→-96, 4级阶梯 |
| 3.5 | **斜坡段4** | z=4608→4096, 高度 -96→-128, 4级阶梯 |
| 3.6 | **Mid 平直段** | z=4096→2048, 高度保持 -128, 对齐 Mid Doors 前区域 |
| 3.7 | **清理视野遮挡** | 移除/调整 Top Mid mass 块，确保 T→Mid→CT 视线通畅 |
| 3.8 | **Mid Doors 优化** | 确保门洞宽度和高度的对狙可行性(宽度192HU足够) |

**关键: 斜坡使 T 出生(z=6656)高于 Mid Doors(z=2048) 128 HU，形成高地优势，符合真实 CS:GO DUST2 的 T 侧高地→低地战术地形。**

## 问题4: B区格局完全不对

### 现状 vs 真实 CS:GO DUST2 B区对比

| 元素 | 真实 DUST2 | 当前代码 | 状态 |
|------|-----------|---------|------|
| B 平台 | 后墙边缘平台 | 居中平台 (z=-1280) | ❌ 位置偏前 |
| Car (汽车) | 平台右侧 | z=-1408, x=2688 | ⚠️ 位置大致对 |
| Back Plat | 左后角高台 | z=-1728, x=2176 | ⚠️ 需要验证 |
| Double Stack | 平台左前 | z=-1408, x=2240 | ⚠️ 需调整 |
| Default 箱 | 平台右前 | z=-1408, x=2368 | ⚠️ 需调整 |
| B Window | 西墙望向 B Tunnels | z=-1216, x=1920 | ⚠️ 位置偏差 |
| B Doors | 西南墙通向 CT Mid | z=-1536, x=1920 | ✅ 大致正确 |
| B Tunnel 出口 | 东墙 | z=-896, x=2176 | ✅ 大致正确 |
| 北墙 | 一整面 | 一整面 | ✅ |
| 南墙 | 一整面 (z=-256) | 一整面 | ✅ |

### 具体问题

**根因**: B Site 平台放在了 (2560, -1280) 而非靠后墙位置。

**真实 CS:GO DUST2 B 区布局**:
```
        北墙 (z=-1920, 一整面)
    ┌─────────────────────────────┐
    │  Back Plat    │  平台+Car   │  
    │  (左后角)     │  (右后方)   │
    ├───────────────┤             │
    │  Double Stack │   Default   │
    │  (左前)       │   (右前)    │
    │               │             │ 东墙
西墙├ B Window ────┤             ├→B Tunnel
    │ B Doors ─────┘             │  出口
    │              斜坡区域       │
    └─────────────────────────────┘
        南墙 (z=-256, 一整面)
```

当前代码中平台在 z=-1280 是正确的 — 但真实 DUST2 的 B 平台应该更加**靠后**（更靠近北墙 z=-1920），且平台应该比 A 平台的规模小。

### 修复方案

| # | 元素 | 当前值 | 改为 | 说明 |
|---|------|--------|------|------|
| 4.1 | B 平台底座 | z=-1280, w=640, d=448 | z=-1536, w=512, d=384 | 平台向后退256，更靠后 |
| 4.2 | Car 位置 | z=-1408, x=2688 | z=-1664, x=2560 | 移到平台右侧后方 |
| 4.3 | Back Plat | z=-1728, x=2176 | z=-1856, x=2048 | 移到左后角 |
| 4.4 | Double Stack | z=-1408, x=2240 | z=-1600, x=2176 | 平台左前位置 |
| 4.5 | Default 箱 | z=-1408, x=2368 | z=-1600, x=2432 | 平台右前位置 |
| 4.6 | B Window | z=-1216 | z=-1024 | 窗口北移至隧道出口视线 |
| 4.7 | 平台前沿 lip | z=-1024 | z=-1344 | 随平台移动调整 |
| 4.8 | 平台后沿 lip | z=-1536 | z=-1728 | 随平台移动调整 |
